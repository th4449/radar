# Conventions for this repository

Read BUILD_PLAN.md first. It is the specification. If part of it looks wrong, say so and explain before changing course.

## What this is

A public tool that names companies and tells communities a data center may be coming. People act on it. Accuracy and traceability matter more than speed or coverage.

## Hard rules

- This repository is public. Never commit keys, tokens, reviewer data or subscriber emails. When a secret is needed, stop and ask the owner to add it as a GitHub or Supabase secret.
- Stop and ask before anything in BUILD_PLAN.md section 11. That includes paid resources, real email, making the site public, lifting the admin gate, any reviewer approval, the Texas county list and scoring thresholds after the backtest.
- A research pass handed to a subagent carries the same rules as a collector. Tell it so in its brief: a plain connection only and never a stealth proxy, stay off every host marked restricted in `config/tx_agenda_platforms.csv` and `config/sources.yaml`, stop at a 403 or 429, and do not open FracTracker's map or its service. On November 22, 2026 a brief left this out and six pages were read against a block.
- A research pass also checks each host's robots file before the first read, and a second read by a separate pass follows. A site is closed when its file bars every program, bars an AI reader that acts for a user under any name, or does not answer 200 or 404. Never switch tools to get past it, and never open a reprint of a closed paper's story. On November 22, 2026 the trial skipped the robots check and 13 cited lines had to be set aside.
- Before writing a collector, open the source, read its terms of use and robots rules and write a note in `docs/sources/<source-id>.md`. If the source restricts automated access, set `method: manual` in `config/sources.yaml`, tell the owner and move on. Never work around a block, a captcha or a login.
- **A source marked `hand_saved: true` is saved by a person, not read by a job.** Its site refused the reader and its page is still public. A person saves the page in a browser and stores it with `python -m collectors.by_hand <source-id> <file>`, which makes no request, checks the file with the collector's own parser and marks the record as saved by hand. Only the owner marks a source this way. The Comptroller's list of registered data centers is the one such source, since November 23, 2026. Never use the command on a file a program fetched.
- **A source marked `hand_entered: true` takes one record at a time from a person,** with `python -m pipeline.hand_entry`: the record's saved file and its facts. The command checks the facts against the file, needs a reason as every record does, refuses a party that may be a person and keeps the file with its hash. Only the owner marks a source, and never one whose terms bar storing its content: entering by hand is not a way around a site's terms. No source is marked yet.
- A source with `verified_at: null` in `config/sources.yaml` must not be fetched by a scheduled job.
- Collector tests use fixtures in `tests/fixtures`. Tests never touch a live site.
- Live requests are slow and identify the collector in the user agent with the contact address from the `RADAR_CONTACT` setting.
- Never state that a data center is planned unless a source says so. Write "signal", not "plan".
- Do not publish names of private individuals. Companies, LLCs and public officials acting in office are in scope.

## Layout

- `config/` YAML that drives everything. `pipeline/config.py` validates it and `tests/test_config.py` checks the files.
- `collectors/` one module per source under `tx/` and `mi/`. Shared fetch and archive code is in `collectors/base.py`.
- `pipeline/` extract, classify, entities, geocode, score. `signals.py` turns one stored document into draft signals and touches no database. `process.py` runs it over the database. `triage.py` is the optional model step, off by default. `alert_email.py` works out the alert emails that are due. It does a dry run unless the owner has unlocked sending, and a dry run prints no address and no unsubscribe token. `email_sender.py` hands a batch to the provider. `collectors/hosted_archive.py` is the archive in the hosted project's storage, and `archive_from_env()` picks the store a job uses.
- `web/` the public site and the reviewer desk. Astro, with Preact for the screens that read data. A static build: every page reads the database in the browser with the visitor's own session, so the policies decide what anyone sees. Never put a rule only in the front end. See `web/README.md`.
- `config/tx_agenda_inventory.csv` every commissioners court, city council, planning body and development corporation in the 30 counties, with its agenda page and platform. `pipeline/agenda_inventory.py` loads it and refuses a row that names a platform its own addresses do not show. Research, not a collector.
- `config/tx_agenda_checks.csv` independent second reads of the inventory's pages. `pipeline/agenda_checks.py` gives every row a verdict. **An agenda collector takes a row only if `collectable()` says so,** which means an independent check confirmed it within the last 180 days. A check records what was on the page and never names a platform. Never write a row and its confirming check from the same read.
- `config/tx_agenda_platforms.csv` each agenda platform's standing under its vendor's terms and its robots file. A collector reads a platform only when it is `cleared`, which takes a reading with nothing against it and the owner's word. CivicPlus products are restricted by the vendor's terms. A `candidate` is a platform with nothing found against it that the owner has not cleared. Do not clear a platform yourself. A new outside service gets its own name and address pattern in `pipeline/agenda_inventory.py`, not `other`. Before saying a page holds plain links, ask for it with no script: a browser shows a list that a script drew, and the collector would not see it.
- `config/tx_agenda_site_terms.csv` what each government's own site says. A government is read only if its row there is `own_pages_silent` or `no_terms_found`, or `noncommercial_cleared`: a site whose terms allow non-commercial use, which the owner has cleared by name. Never set that mark yourself. Three Michigan sites carry it since November 25, 2026. Texas' four sites with like terms do not.
- **Michigan's agendas use the same code with their own files** (milestone M11): `config/mi_places.csv` (every city, village and township in Allegan, Kalamazoo, Monroe, Oakland, Washtenaw and Wayne counties, from the Census), `config/mi_agenda_inventory.csv`, `config/mi_agenda_checks.csv` and `config/mi_agenda_site_terms.csv`. Every loader in `pipeline/agenda_inventory.py` and `pipeline/agenda_checks.py` takes `state=` and reads Texas when none is given. The platforms file is shared. Michigan's kinds of body are `county_board`, `city_council`, `township_board` and `village_council`; `agenda_inventory.GOVERNING` lists every kind that governs. Two townships share a name and are written with their county: "Salem township (Washtenaw County)". The two agenda processors read the state from the source id (`mi_agendas_legistar`, `mi_agendas_own_sites`). **Both Michigan sources are `manual` and no collector reads them** until rows are confirmed and each site's terms and robots file are read.
- `collectors/tx/agenda_pages.py` reads the agenda pages of governments that post files on their own sites, then their recent agenda files. One source, many sites: a refusal closes that site for the run and is recorded in `config/tx_agenda_site_terms.csv` as `refused`, never retried. It follows a file only on the government's own site or its site builder's file host. Five counties' sites are provided by the Texas Association of Counties (platform `cira_county_site`): three keep agendas in a calendar drawn by a script, and the collector reads that calendar's RSS feed, whose address the page gives, never the page's script calls. A date is read from the page's words before a file's name, and an unsure date is no date: a month and a year give a month, kept as `month`, never a day. A site built and hosted by a vendor whose terms bar a collector is marked `vendor_site` and stays closed: look for the vendor's credit in the footer, not only for a terms page. A host that serves one government's own files counts as that government's site, for its pages only, when it is listed in `OWN_FILE_HOSTS`: each is there on the owner's word, after the reader asked the host for its robots file. Otsego's delivery host is the one such host. The summary of an agenda signal never carries a file name or a link's text: both can name a person.
- `pipeline/ocr.py` reads a PDF that has no text at all with Tesseract, a program installed with `brew install tesseract` or `apt-get`, not a Python package. Nothing leaves the machine. Text read this way is marked on the stored document (`raw_meta.ocr`) and on any signal made from it, in the summary too. Without Tesseract a scan is stored unread and nothing fails. Tests that need it skip unless `RADAR_REQUIRE_OCR=1`, which CI sets.
- `collectors/tx/legistar.py` reads agendas through the Legistar Web API and never fetches an agenda file: the hosts that hold them bar robots. An agenda names people, so the source is `personal_rows` and an agenda signal's summary never quotes an item.
- `scripts/dev_seed.py` fills a local database from the test fixtures. It refuses any other database.
- `scripts/backup.py` dumps the radar's own schemas and proves a dump restores: `trial` restores it into a scratch database on this computer and counts every table. **A dump holds subscribers' addresses.** The command refuses to write one inside the repository. Never upload one as a workflow artifact.
- **Real runs are the owner's switch.** Every workflow is a dry run, or does nothing, unless the repository variable `RADAR_LIVE` is the word true. The owner set it to true on November 26, 2026, and the database's address and the archive's key are both set, so a workflow started now is a real run that fetches and keeps records. Never start one, put a schedule in a workflow or hard-code that switch without the owner's word. The same holds for `policy-tests.yml`, which runs the policy tests on the hosted database: it writes rows and rolls them back, and it never gets a schedule.
- `db/migrations/` SQL migrations named `<UTC timestamp>_<name>.sql`. `supabase/migrations` is a symlink to this folder so the Supabase CLI finds them.
- `tests/db/` policy tests. They run against `supabase db start`.
- `docs/sources/` one note per source. `docs/services/` one note per outside service the site leans on. `docs/progress.md` gets a few lines at the end of every session.
- **The hosted database is a Supabase project named `radar`,** created on the owner's word on November 25, 2026. It holds the schema and no row. Apply a new migration to it with `supabase db push` from the linked checkout, which keeps the ledger under the files' own numbers, and only on the owner's word. The stored history is not there: it is in `radar_backtest` on the owner's computer. Do not write "the hosted database" for the history database: notes of November 24, 2026 did, and were corrected. Its address and service key are secrets the owner adds. Never print or commit either.
- `docs/launch_checklist.md` what stands between the radar and launch, and who does each step. `docs/runbook.md` what an administrator does and what to do when something breaks. Keep both true when a rule or a screen changes.
- `pipeline/study.py` is the money cross-reference (milestone M12). `collectors/us/qpq_data_center_payers.py` keeps a copy of the QPQ Tracker's data center study page and reads its table of payers. Every processing run rebuilds `study_payers` and `entity_study_payers` from the newest stored copy. A match is by whole name, with a legal form at the end set aside. It is never proof of the same company and the pages say so. `config/study_payers.yaml` holds a payer's other names. Each is a name the study's own page writes, or a company a public filing says is the payer's, with the filing's address: add one of those only after reading the words in the filing and on the owner's word, never because a name looks related. A name listed with its legal form meets a record only as written. The site's API is barred by its robots file and is not called. The public alert gives the payer's name as the study writes it and a link to the study, never the name a record gave. The owner switched the source on on November 25, 2026: its job is started by hand. No copy is stored until a real run.
- `pipeline/reread.py` notes which pages of a stored PDF hold no words, for files stored before November 24, 2026, and gives any signal made from one the file's own page numbers. It writes nothing unless given `--write`, changes no stored text and fetches nothing from any site. Dump the database before running it with `--write`.
- `pipeline/health.py` says which sources need a person, from the run log: a failed run, a refusal, a source nobody has read for too long, a page a person is due to save. It writes and sends nothing. `.github/workflows/monitor.yml` runs it, by hand only until launch.

## Public site and alerts

- The anonymous key reads one thing: the view `public_alerts`. Keep it narrow. Its `reference` for each record is a number, never a name or a summary.
- Anything a stranger may write goes through a function with its own limits, as `submit_correction()` and `unsubscribe()` do. Never grant the anonymous key a table.
- A subscriber's address is never shown, logged or printed: not on the administrator desk, not in a run log, not in a dry run's output.
- Only `confirm_subscription()` sets `confirmed_at`. It checks that the sign-in service proved the address.
- **The public site will be at `standuptocorruption.org/radar`,** the owner said on November 26, 2026. It is not hosted yet. The build works under a path: `RADAR_BASE_PATH=/radar npm run build`. Every link in `web/src` goes through `href()` in `web/src/lib/paths.ts`, and a test fails on one written by hand. See `docs/launch_checklist.md` part 2a.
- **Sending real email is the owner's decision.** The email job is a dry run unless it is given `--send`, and `--send` is refused unless the owner has set all three locks: the variable `RADAR_EMAIL_LIVE`, the secret `RESEND_API_KEY`, and the site's address and the from address in `config/email.yaml`. See `pipeline/email_sender.py`. Never set a lock, fill in those addresses or weaken a lock without the owner's word. An error from the sender names no person and no key.
- After changing `config/counties_*.yaml` or `config/sources.yaml`, run `uv run python scripts/export_web_data.py`.
- **A rule on data centers that a government is weighing is an alert too:** a moratorium, a zoning change. The owner decided this on November 23, 2026. A reviewer confirms it when the record says so. A government buying data center services for its own computers is not an alert.
- Public copy follows the standing rules: the language of signals, short sentences, no boxes and chips.

## Processing

- A record becomes a signal only with a stated reason, and the reason is stored with it. A summary restates the record.
- A record whose named party does not show a company or a public body makes no signal. Count it by its number. Never write its name anywhere: not in a signal, a log or a test.
- A source that is a list naming people has `personal_rows: true` in `config/sources.yaml`. Its documents are stored restricted and a reviewer cannot read them.
- Never send a record that may name a person to an outside service, the geocoder and the model included.
- Bump `RULES_VERSION` in `pipeline/signals.py` when a rule changes. Reading documents again only adds signals.
- The model's answer is stored beside a signal. It never creates, removes or rewrites one.
- An agenda signal carries no company. **An agenda record that says "data center" is held to its government and meeting** (`extracted.meeting`), so it can sit on a site and reach a reviewer. A code word alone opens no site. On Legistar, as in an agenda file, a "Project" code name is a reason only where the item speaks of economic development negotiations. The owner approved both on November 23, 2026 after the backtest, with a review threshold of 3. The scoring file is still a placeholder.
- **In an agenda, the words "data center" are set aside when the item is about the government's own computers:** a hosting contract, a server room's cooling. The words that show it, and the words for land or a project that always win over them, are under `own_computers` in `config/keywords.yaml`. Add a word there only from a record somebody has read. The owner decided this on November 23, 2026. Another term in the same item still counts.
- `sites.py` groups signals into sites and scores them at the end of every run. A signal already on a site never moves, and a job never merges, splits, confirms or rejects a site. The database refuses a status change from a job other than candidate to in_review.
- `backtest/harness.py` judges known projects against dated signals for milestone M9. It reuses the rules of `cluster.py` and `score.py` and touches no database. A signal counts from the day it could be seen. The words hit, miss and false alarm are defined at the top of the file. The known projects, their public dates and the control counties are the owner's to approve.
- `backtest/known_projects_tx.csv` the backtest's list of known projects, one row per site, with the first news report (the public date, the owner's definition) and the earliest record found. `backtest/projects.py` loads it and refuses a row that breaks a rule. `backtest/known_projects_hosts.csv` holds the robots result for every site a read rests on, and a test refuses a read on a closed site. `backtest/known_projects.md` says how the list was made and what is not verified. Research, not a collector.
- `backtest/history.py` reads stored history as dated signals for the harness and writes nothing. Three things there are the backtest's own: it reads the control counties too, a signal counts from the day its record could be seen (`seen_on()`, the later bound where the day is not kept), and a company counts as listed only from the day its registration took effect. It also says which known project a record names, by the project's company beside the words "data center" or by a "Project" code name. The everyday pipeline cannot do that, and the report counts such ties apart. `backtest/run.py` runs it and `backtest/report.py` writes `backtest/report_tx.md`, which is never edited by hand. `backtest/findings_tx.md` is written by hand and holds what the backtest shows and the thresholds proposed to the owner. **A signal that fits no known project is unreviewed, so the report never names it** and the full listing (`--listing`) stays outside the repository.
- A history run reads older records once, for the backtest: `python -m collectors.run <source> --history-since 2023-01-01`. Legistar, the ERCOT planning group, governments' own agenda pages and the well reports each have the setting, a `history()` class method. It reads only what an everyday run may read, at the same pace, and skips what is stored, so it can be started again. `config/counties_tx_control.yaml` holds the eleven control counties the owner approved. The radar does not watch them. History is kept outside the repository and outside iCloud, in `~/.local/share/radar/backtest/`, with `DATABASE_URL` set to a database of its own, `radar_backtest`, on the local Postgres. The database tests expect the default database to be empty, so history never goes there. Dump `radar_backtest` before any `supabase db reset`.

## Database

- Every table in `public` has row level security on. A test fails if one does not.
- The anonymous key reads only the view `public_alerts`. Nothing else.
- Section 7 of the build plan is enforced in policies and triggers, not in the front end. Write the test before the policy.
- `reviewers.status` and `reviewers.role` change only through an administrator who is not the target, or by the owner by hand in SQL. The service role cannot approve anyone.
- Settings that policies depend on live in the table `app_settings`, not in YAML.
- Helper functions live in the `private` schema, which the API does not expose.

## Working style

- Python 3.12, managed with uv. `uv run ruff check .`, `uv run ruff format .` and `uv run pytest` must pass before a commit.
- Small commits with clear messages.
- Write tests first for RLS and scoring.
- When a fact about a source, a price or a law matters to a decision, check it. Say plainly what could not be verified.
- Prose is American English with no serial comma. Short and concrete.
